# Deploying to Replit

1. **Create Repl → Import from GitHub →** `ea-13/winwork`.
2. **Tools → Secrets**, add seven:

   | Key | Value |
   |---|---|
   | `SUPABASE_URL` | from `.env` |
   | `SUPABASE_ANON_KEY` | from `.env` |
   | `SUPABASE_SERVICE_ROLE_KEY` | from `.env` |
   | `ANTHROPIC_API_KEY` | from `.env` |
   | `VITE_SUPABASE_URL` | same as `SUPABASE_URL` |
   | `VITE_SUPABASE_ANON_KEY` | same as `SUPABASE_ANON_KEY` |
   | `NODE_ENV` | `production` |

   **Do not add** `DATABASE_URL` or `SUPABASE_DB_PASSWORD` — migrations run from
   a developer machine, and the app never needs them.

3. **Run**. The build compiles the client, checks no secret reached the bundle,
   then compiles the server. `npm start` serves the API and the built client on
   one port.

## Two things that bite

- **`VITE_*` are consumed at build time, not runtime.** Missing during the build
  means the browser gets `undefined` while `/api/health` looks perfectly green.
  Most confusing possible failure.
- **Deployments can have a separate secrets pane** from the workspace. Check
  both; workspace-only secrets are the usual cause of "works in the editor,
  dead when deployed".

## Do not let Replit commit

Its Version Control panel will offer to. Treat the Repl as pull-only — two
writers on a repo used as the source of truth produces merge conflicts nobody
wants during a demo.
